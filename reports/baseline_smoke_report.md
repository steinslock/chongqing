# Chongqing Binary Diagnosis Baseline Report

## Technical Summary

- Best locked-test AUROC is `0.6667` from `eeg_rest_logistic_regression` on `eeg_rest`; this is a fixed-split baseline, not a tuned final model.
- Evaluation uses `subject_splits_v1`: five out-of-fold CV validation folds from the CV pool plus one locked-test evaluation trained only on the CV pool.
- All thresholded metrics use the fixed threshold `0.5`; the locked test set is not used for feature selection, hyperparameter tuning, threshold tuning, or early stopping.
- Demographics models use cleaned age, sex, grade, and grade group only. Diagnosis, CDRS, CES-DC, HAMA, SCARED, self-harm, suicide, and other clinical scale fields are blocked by the leakage guard.

## Scope, Data, And Metric Definitions

- Primary label: `primary_label_nonhealthy` with `1` as non-healthy and `0` as healthy.
- Split file: `/data4/qiangminc/code/chongqing/artifacts/splits/subject_splits_v1.csv`; SHA256 `50680a42e69a0331e47fe59686050c6a01e385784b182f88f07a64aa6bc5f12c`.
- Reported unit: subject-level prediction, one row per subject per model and evaluation stage.
- Metrics: AUROC, AUPRC, Balanced Accuracy, Macro-F1, Sensitivity, Specificity, PPV, NPV, Brier Score, 10-bin Expected Calibration Error, and 10-bin Maximum Calibration Error.
- Uncertainty: `50` bootstrap resamples over subject-level predictions for each model and evaluation stage.

## Available Feature Families

- `no_information`: available, subjects `96`, features `0`. No feature table required.
- `demographics`: available, subjects `96`, features `4`. Cleaned ordinary demographics from subject_splits_v1 only.
- `eeg_rest`: available, subjects `96`, features `533`. Existing v1 EEG Rest traditional feature table.
- `fnirs`: skipped. No reliable subject-level fNIRS traditional feature table is currently available in the organized project tree.
- `face`: skipped. No reliable subject-level Face traditional feature table is currently available in the organized project tree.

## Methodology And Leakage Controls

- Majority and stratified-random baselines use no subject predictors; a dummy zero column is passed only to satisfy the estimator API and is counted as zero features.
- Demographics-only Logistic Regression and the configured boosting classifier use pipeline-fitted imputers/encoders inside each fold or final CV-pool fit.
- EEG Rest Logistic Regression, Random Forest, and the configured boosting classifier use the existing v1 Rest EEG feature table with configured non-clinical prefixes only.
- The fNIRS and Face interfaces are represented in config, but no fNIRS/Face results are reported because no reliable subject-level traditional feature table is currently configured.

## Limitations, Robustness, And Next Steps

- These are conservative baseline runs with fixed hyperparameters; they establish reproducible references rather than optimized clinical models.
- EEG results cover only the existing Rest traditional feature table. Oddball/1BACK or future fNIRS/Face feature tables should be added through `configs/baselines/default.yaml` and rerun under the same split protocol.
- Before any deep or multimodal model comparison, keep the locked test untouched and compare candidate development using CV-pool evidence first.
